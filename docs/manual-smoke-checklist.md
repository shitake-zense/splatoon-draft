# 手動スモークテスト チェックリスト

自動テストが無いため、変更の前後でこのチェックリストを手動実施し結果を記録する。
`fetch('data/weapons.json')` のため `file://` ではなく HTTP 配信が必要。

## 起動
```
# リポジトリ直下で
python -m http.server 8000
# → http://localhost:8000/ を開く
```
- Firebase 本番DBに接続されるため、テスト用ルームID（実運用と被らない）で確認すること。

## シナリオ

### S1. ソロ：各PICK順が最後まで進む
- 交互 / スネーク / クラシックスネーク / ミドルスネーク / バランス(a121) / 前重ね(a211) / 同時ピック
- 各順でドラフト開始→BAN→PICK→リザルトまで到達すること。

### S2. マルチ 2v2（代表者ピック / 個人ピック）
- 部屋作成 → URL/ID 共有 → 参加 → チーム編成 → 開始 → BAN（代表者 / 個人）→ PICK → リザルト。
- 個人ピックで人数が揃うまで開始ボタンが無効。

### S3. 同時ピック 2v2（修正#2の主検証）
- 各ラウンドで担当ペア（Alpha[i] と Bravo[i]）の2人だけが送信でき、担当外はグリッド操作不可。
- アルファ側の非ホスト参加者が誤って bravo 扱いにならない。`pending_bravo_pick` の相互上書きが起きない。
- 被りOK：同武器を両者がピックしても確定して次ラウンドへ進む。
- 3v3 / 4v4 でも各ラウンドの担当ペアのみ送信可能。

### S4. ピック順チップ表示（修正#3）
- 同時ピック中、各ラウンド（ペア）が1ボックスにまとまり、人数分のボックスが並ぶ。
- 「同時 同時 …」固定文言が出ない。現在ラウンドが強調される。

### S5. 再参加（修正#4）
- 同一ブラウザでロビー離脱→再参加で、既存スロット（team・ピック順割当）が維持される。
- 改名して再参加しても同一スロットが維持される（memberId 基準）。
- 別ブラウザからは乗っ取りが起きない。

### S6. スピナー（修正#1）
- グリッドに「スピナー」カテゴリボタンが出る。13武器が画像付きで表示。
- 「標準武器のみ」モードで標準スピナー6種が出る（デコ/コラボ/レプリカ等は出ない）。
- スピナーを BAN / PICK しても破綻しない。

### S8. 武器の絞り込み（武器種/サブ/スペシャル）
- ホストのルール設定で「🚫 武器の絞り込み」を開くと、武器種・サブ・スペシャルのチェックリストが展開。
- チェックした要素のいずれかを持つ武器が、BAN/PICKグリッドと自動ランダム選択から消える。
  - 例1: チャージャーのみチェック → チャージャーがピック不可。
  - 例2: ウルトラショット以外の全スペシャルをチェック → special=ウルトラショットの武器のみ表示。
  - 例3: サブ=カーリングボム・スペシャル=テイオウイカをチェック → そのどちらかを持つ武器が全消去。
- 「ピック可能: X / 総数」の残数表示が更新される。設定はロビーに同期し、ホスト再参加で復元される。
- 「標準武器のみ」との併用で両条件が積み重なる。

### S9. モバイル横溢れ（#1）
- 幅 ≤390px（iPhone相当）でドラフト中の両チームパネルが 50/50 を維持。
- 長い武器名（例「カーボンローラーデコ」「スクリュースロッシャーネオ」）が `…` 省略。
- 横スクロール/溢れが無い。結果画面の2カラムも崩れない。PC幅でも回帰なし。

### S10. 相手ピックモード（#2 enemy）
- ホスト設定（およびソロ設定）のピックモードに「🆚 相手ピック」がある。
- enemy モードで、アルファの選択がブラボーのロードアウトに、ブラボーの選択がアルファに入る。
- ピック順（交互/スネーク等）通りに手番が回る。プロンプトに「相手に使わせる武器」と表示。
- BAN は通常どおり（相手BANにならない）。結果画面で各チームの使用武器が正しく表示。
- 個人/代表者モードに回帰なし。（注: 同時ピックとの併用は v1 非対応）

### S11. 結果画像ダウンロード（#3）
- 結果画面の「🖼️ 結果画像を保存」で PNG が生成・保存される。
- ステージ・ルール・両チームの BAN/PICK が欠けず描画（個人ピックはプレイヤー名併記）。
- 武器画像欠落でも落ちない。各ピックモード（enemy含む）で正しい使用武器が出る。
- iOS アプリ内ブラウザでは画像が新規タブで開く場合あり（長押し保存）。

### S12. アイコン / PWA（#4）
- タブ/ブックマークにアイコン表示。スマホ「ホーム画面に追加」でアイコン・名前反映・standalone 起動。
- GitHub Pages サブパスで manifest.json が 404 にならない（相対参照）。

### S13. ジャンルBAN（武器種/サブ/スペシャル単位・代表者BAN限定・ジャンル別BAN数）
- 設定の「ジャンルBAN」行は **代表者BAN/代表者ピック（＝個人ピック×個人BAN以外）のときだけ表示**。武器種/サブ/スペシャルごとに **BAN数（0〜4）** を設定できる（マルチのルール設定・ソロ設定の両方）。デフォルト全0＝従来挙動と一致。
  - 個人ピック＋個人BAN：行が**非表示**。
  - 個人ピックでBANモードを「代表者BAN」に切替：行が**表示**。
  - 代表者ピック／相手ピック：BANモード行は隠れるが、ジャンルBAN行は**表示**。
- いずれかを1以上にして開始 → BANフェーズのグリッド上部に粒度タブ `[ブキ][サブ][スペシャル][武器種]`（数>0のものだけ）が出る。武器BAN数(Ban数)が0なら最初のジャンルタブが初期選択。
- タブ切替で、サブ/スペシャル/武器種のアイコン付き正方形タイルが並び、タップ→2タップ確定でBAN（武器BANと同操作）。各タイルに「N種」（消す武器数）表示。
- **種別ごとに別枠**：武器BANはBan数まで、サブBANはサブBAN数まで…と各上限が独立。合計＝Ban数＋各ジャンル数。BANスロット数も合計に増える。
- ヒントに「残り: 武器×N・サブ×N…（タブで種別を切替）」と内訳が出る。全種別を埋めるまで送信/確定は無効。
- 確定したジャンルBANに該当する武器は「ブキ」タブ・PICKフェーズで全グレーアウト。タイマー自動補完も各種別を上限まで埋め、ジャンルBAN済み武器は選ばない。
- BANスロット・結果画面・結果画像で「サブ：◯◯／スペ：◯◯／武器種：◯◯」とアイコン付き表示。結果画像の設定概要に「代表者BAN×3(+サブ1)」のように出る。
- マルチ：代表者のみがジャンルBANを操作でき相手チームへ同期・自動確定。`pending_*_bans` に undefined を含めない。
- 個人BANモードではジャンルBAN無効（タブが出ない）＝従来の個人BANに回帰なし。

### S14. お題カード / 縛りルーレット（Phase 2・完全クライアント完結）
- 設定（マルチのルール設定・ソロ設定の両方）に「🎯 お題カード（縛りルーレット）」トグルがある。デフォルトOFF＝従来挙動（お題なし）。
- ON にして開始すると、ドラフト画面入場時に**ルーレット演出**（お題ラベルが回って1枚に確定）が出る。タップで閉じられ、進行はブロックしない。
- マルチ：ホストが抽選した**同じお題**が参加者側にも同期表示される（`state.challenge` 経由）。
- 結果画面に「🎯 お題：◯◯」と、各チームの達成（○ 達成 / × 未達成）が表示される。**非強制**＝ピックは制限されず達成可否を表示するのみ。
- 結果画像にもお題バンド（お題ラベル＋両チームの ○/× ）が描画される。
- enemy（相手ピック）モードでも、各チームの「使うロードアウト」（=`picks[team]`）で達成判定される。
- OFF のときは結果画面・結果画像にお題表示が出ない（`#r-challenge` 非表示）。
- 後方互換：お題なしで保存された既存ルーム（`state.challenge` 無し）でもエラーにならない。

### S7. 既存機能の非回帰
- タイマー切れ自動送信（仮選択優先→ランダム）の優先順位。
- ホストの「ロビーに戻る」で参加者が自動でロビー待機へ戻る。
- kick による退出。
- URL `?room=XXXX` 自動参加、ID/URL コピー。

## データ検証
- `node -e "JSON.parse(require('fs').readFileSync('data/weapons.json','utf8'))"` がエラー無し。
- 既存 key を壊していない（追加のみ）。追加 imgFile が `images/weapons/` の実ファイルと一致。
